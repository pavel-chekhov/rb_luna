## 1. События

Блок — панель управления каталогом, вкладки и карточки игр и провайдеров. Передавайте события по [Общим правилам dataLayer](1.%20dataLayer.md).

| Событие | `object_type` | Когда отправлять |
| --- | --- | --- |
| `search_input_changed` | `search_input` | При первом вводе символа в пустую строку поиска, один раз за показ страницы |
| `button_activated` | `button` | При активации кнопки «Провайдеры» пользователем |
| `nav_tab_selected` | `nav_tab` | При фактической смене активной вкладки после инициализации, по состоянию маршрута |
| `game_card_viewed` | `game_card` | При выполнении условия показа карточки; для `random_game` — при каждом выпадении игры после прокрутки барабана |
| `game_card_activated` | `game_card` | При активации карточки игры пользователем |
| `provider_card_viewed` | `provider_card` | При выполнении условия показа карточки провайдера |
| `provider_card_activated` | `provider_card` | При активации карточки провайдера пользователем |

Условия показа для `viewed` согласуйте по [разделу 5](#5-что-уточнить-перед-реализацией).

## 2. Элементы и свойства

Панель управления: строка поиска — `object_name = games`, кнопка «Провайдеры» — `object_name = providers`.

Для карточек игр берите `object_name` и строковое свойство `provider` из каталога игр продукта. Для карточек провайдеров берите `object_name` из справочника провайдеров. Источники справочников — `TBD`, [раздел 5](#5-что-уточнить-перед-реализацией).

### 2.1. Вкладки

| Вкладка | `object_name` | Текущий `element_position` |
| --- | --- | --- |
| Лобби | `lobby` | `1` |
| Слоты | `slots` | `2` |
| Live-казино | `live_casino` | `3` |
| Crash | `crash` | `4` |
| Настольные | `table` | `5` |
| Провайдеры | `providers` | `6` |

### 2.2. Ленты лобби

| Лента | `container_name` | Тип карточек |
| --- | --- | --- |
| Рекомендации | `recommended` | `game_card` |
| Популярные | `popular` | `game_card` |
| Новые | `new` | `game_card` |
| Джекпот дня | `daily_jackpot` | `game_card` |
| Случайная игра | `random_game` | `game_card` |
| Горячие игры за 24 часа | `hot_24h` | `game_card` |
| Лучшие LIVE | `top_live` | `game_card` |
| Провайдеры | `providers` | `provider_card` |

### 2.3. Полный состав payload

Обозначения в шаблонах: `position` — текущая позиция с `1`; `lobbyCollectionName` — имя игровой ленты из [раздела 2.2](#22-ленты-лобби); `tabName` — `slots`, `live_casino`, `crash` или `table`; `providerName` — идентификатор провайдера выбранной коллекции; `activeTabName` — имя активной вкладки из [раздела 2.1](#21-вкладки); `gameProvider` — поставщик игры из каталога продукта. Подставляйте значения вместо обозначений.

| Элемент и место | Полный `payload` |
| --- | --- |
| Поиск `games` и кнопка `providers` на панели управления | `{container_type: 'catalog_toolbar'}` |
| Вкладка в таб-баре | `{container_type: 'tab_bar', element_position: position}` |
| Игра в ленте лобби | `{container_type: 'collection', container_name: lobbyCollectionName, parent_container_type: 'tab_panel', parent_container_name: 'lobby', element_position: position, provider: gameProvider}` |
| Игра на вкладке `slots`, `live_casino`, `crash`, `table` | `{container_type: 'collection', container_name: tabName, parent_container_type: 'tab_panel', parent_container_name: tabName, element_position: position, provider: gameProvider}` |
| Игра в коллекции выбранного провайдера | `{container_type: 'collection', container_name: providerName, parent_container_type: 'tab_panel', parent_container_name: 'providers', element_position: position, provider: gameProvider}` |
| Игра в результатах поиска | `{container_type: 'collection', container_name: 'search_results', parent_container_type: 'tab_panel', parent_container_name: activeTabName, element_position: position, provider: gameProvider}` |
| Провайдер в ленте `providers` лобби | `{container_type: 'collection', container_name: 'providers', parent_container_type: 'tab_panel', parent_container_name: 'lobby', element_position: position}` |
| Провайдер на вкладке `providers` | `{container_type: 'tab_panel', container_name: 'providers', element_position: position}` |

Для каждой карточки используйте один состав свойств в её событиях `viewed` и `activated`.

Порядок карточек на вкладке `providers` требует уточнения — `TBD`, [раздел 5](#5-что-уточнить-перед-реализацией).

## 3. Порядок отправки

1. События `activated` отправляйте в обработчике пользовательской активации. Каждую повторную активацию учитывайте новым событием. Для `selected` отслеживайте фактическую смену активного маршрута после инициализации, включая программную смену.
2. Для поиска сохраняйте признак отправленного `search_input_changed` на весь показ страницы. Передавайте событие при первом вводе символа в пустое поле.
3. Для каждого факта создавайте `event_id = newId()` и фиксируйте `occurred_at = new Date().toISOString()`. При повторной доставке сохраняйте исходное сообщение.
4. Берите имена и состав свойств из [раздела 2](#2-элементы-и-свойства). Позиции вкладок считайте по текущему порядку в таб-баре, карточек игр — по порядку в коллекции, результатов поиска — по рангу в выдаче, карточек провайдеров — по порядку в их контейнере. Отсчёт начинается с `1`; при прокрутке карусели сохраняйте позицию карточки в коллекции.
5. Для обычных показов используйте `IntersectionObserver` по [Клиентским приёмам 4](helpers.md#4-отслеживание-показа): один `viewed` на карточку за показ её контейнера. Сохраняйте учёт при rerender; при уходе с поверхности завершайте наблюдение, при возврате создавайте новое. Переиспользованный под другой объект DOM-узел ставьте под наблюдение заново.
6. В `random_game` отправляйте `game_card_viewed` для выпавшей игры при каждом результате прокрутки барабана, включая повторное выпадение той же игры.
7. Сохраняйте текущий показ `search_results` до закрытия выдачи. При уточнении запроса продолжайте учёт уже показанных игр; новые игры ставьте под наблюдение. В `parent_container_name` передавайте активную вкладку.
8. Получайте `object_version` из конфигурации, `schema_version` — из сборки для пары «`event` + `object_version`».
9. Перед каждым событием выполняйте `window.dataLayer.push({ payload: null })`. Массовые показы передавайте очередью по [Клиентским приёмам 5](helpers.md#5-планирование-push), сохраняя время факта, состав и порядок сообщений.

## 4. Примеры сообщений

Используйте состав сообщений из примеров; UUID, время, версии и идентификаторы игр и провайдеров приведены для иллюстрации.

Первый символ, введённый в строку поиска:

```js
window.dataLayer.push({ payload: null });

window.dataLayer.push({
  event: 'search_input_changed',
  event_id: 'a1f6c283-4d70-4e19-8b5c-7f2a0d693e41',
  occurred_at: '2026-09-07T10:14:02.315Z',
  schema_version: '1:1',
  source: 'web',
  object_class: 'ui_element',
  object_type: 'search_input',
  object_name: 'games',
  object_version: 1,
  payload: {
    container_type: 'catalog_toolbar'
  }
});
```

Переход на вкладку `Слоты`:

## 5. Что уточнить перед реализацией

1. **Идентификаторы игр.** Указать источник устойчивых значений `object_name` карточек игр. `TBD`.
2. **Идентификаторы провайдеров.** Указать справочник для `object_name` карточек провайдеров, имён их коллекций и свойства `provider` у игр. `TBD`.
3. **Условие показа.** Согласовать долю видимой площади и непрерывную длительность перед внедрением `viewed`. В [Клиентских приёмах 4](helpers.md#4-отслеживание-показа) предложены 80% и 1000 мс. `TBD`.
4. **Порядок карточек провайдеров.** Уточнить передачу `element_position` на вкладке `providers`: [исходное ТЗ](3.%20game_catalog.md) объявляет `tab_panel` неупорядоченным, а реестр и пример требуют позицию. Состав сообщений в этой версии сохранён по исходному реестру. `TBD`.
